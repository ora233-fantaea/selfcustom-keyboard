# KiCad 与官方 DRC 报告

## 一、KiCad 是怎么装上的

**官方安装器装不上**：`kicad-9.0.9-x86_64.exe` 是 NSIS 打包，静默安装（`/S`）在非交互环境需要 UAC 提权，退出码 1。

**改用免安装解包**（不需要管理员权限）：

```bash
7z x -y kicad-9.0.9-x86_64.exe -oKiCad
KiCad/bin/kicad-cli.exe version     # -> 9.0.9
KiCad/bin/python.exe -c "import pcbnew; print(pcbnew.Version())"   # -> 9.0.9
```

位置：`D:\workbuddy-temp\spaces\2026_11_23_22-26-20\_tools\KiCad\`（915 MB，在工作目录下，未纳入版本库）

`kicad-cli` 负责 DRC / 导出，`KiCad/bin/python.exe` 带 `pcbnew` 绑定，可以直接跑 `gen_plate.py`。
另外给这个 python 装了 `shapely`、`matplotlib`（定位板开孔合并与预览需要）。

## 二、解包后暴露的四个 Bug

装上 KiCad 后第一件事就是跑 DRC，结果**直接报「电路板加载失败」**——
也就是说我们之前生成的所有 `.kicad_pcb`，KiCad 根本打不开，而自研的宽松解析器发现不了。
二分定位到四处：

| # | 问题 | 现象 | 修复 |
|---|---|---|---|
| 1 | `(version 20250114)` 比本机 KiCad 的格式版本 `20241229` 新 | KiCad 判定「文件来自更高版本」，**静默返回 null** | 改为 `20241229` |
| 2 | `(generator_version 9.0)` 没加引号 | `9.0` 以数字开头的裸符号无法解析 | 改为 `"9.0"`（`generator` 同理） |
| 3 | `(pad np_thru_hole ...)` 焊盘编号是空字符串而不是空引用 | `_emit` 把空原子直接吞掉，编号丢失，整块板解析失败 | 改用 `K.Str("")` |
| 4 | 布线器把层号 `0/1` 写进 `(layer ...)` | `(layer "0")` 不是合法层名，**布线后的文件全部打不开** | 加 `LAYER_NAME = {0:"F.Cu", 1:"B.Cu"}` 映射 |

第 1 条最阴——KiCad 不报错、不抛异常，`LoadBoard()` 只返回 `None`，靠猜是猜不出来的。

第 4 条是这次顺带挖出来的：`autoroute.py` 里 `path_to_geom()` 返回的是层索引，
直接塞进 `(layer ...)` 就成了 `(layer "0")`。也就是说**之前所有「已布线」的文件，KiCad 一个都打不开**，
134/183 那个数字只在自研解析器里成立。

## 四、布线器重写（2026-11-24）

上一版布线 199 处短路，根因有三个，全部在**障碍模型**，不在 A* 本身：

| # | 问题 | 后果 |
|---|---|---|
| 1 | `soft_open()` 把目标焊盘周围 **pad+0.8mm** 的障碍全清掉 | SOIC 1.27mm 间距下等于把左右邻焊盘一起解锁，走线直接从邻焊盘上碾过去 → 199 短路 |
| 2 | 已布走线只标记路径节点 ±1 格（0.2mm） | 线-线中心距只保证 0.2mm，扣掉两条线宽实际间距 0 → 走线交叉 |
| 3 | 布线器完全不知道 Edge.Cuts 存在 | 89 处走线侵入开槽边缘 |

重写后的 `router.py`：

- **障碍按真实几何栅格化**：焊盘用外框、钻孔用圆、开槽/板框用矩形，统一外扩 `0.2 + 线宽/2`；
- **开槽与板边按 0.5mm 板边间距**（`EDGE_INFLATE = 0.63`），与 KiCad DRC 规则一致；
- **占用带网络号**（`int16`），同网可贴合、异网一律禁止，走线按**线段距离**占用而非只标节点；
- **进入焊盘只解锁「本焊盘独占」的格子**（`pad_count <= 1`），被邻居禁区覆盖的格子保持封锁；
- **网格 0.2 → 0.1mm**：1.27mm 间距的 SOIC 在 0.2mm 网格下只有 3.3 格，进焊盘通道差 0.005mm；
- 过孔按 0.595mm 外扩占用、孔-孔最小 0.3mm、换层前检查 5 格半径内的异网占用。

### 结果

| 指标 | 旧版 | 新版 |
|---|---|---|
| 短路 `shorting_items` | **199** | **0** |
| 走线交叉 `tracks_crossing` | 10 | **0** |
| 走线侵入板边 `copper_edge_clearance` | 89 | **0** |
| 走线-焊盘/走线-走线间距 `clearance` | 41 | **0** |
| 孔-铜 `hole_clearance` | 26 | **0** |
| 剩余 `clearance` | — | 19（**全部是 J_USB 封装内部 0.15mm**，连接器固有） |

也就是说：**布线产生的 DRC 违规为 0**，剩下的都是封装自带或丝印外观问题。

### 但覆盖率还不够

| 项目 | 结果 |
|---|---|
| 信号段 | 102 / 183（81 条未布） |
| GND | 134 / 290 |
| VCC | 90 / 96 |
| V5 | 19 / 20 |
| 走线 / 过孔 | 6529 段 / 150 个 |

失败集中在 K56~K75（底行右侧）这类从键区跨越整个芯片带的长网络。
限流手段是单条 10s 超时 + 搜索框 0.55×跨度，超时就判失败——宁可不出线，也不出违反间距的线。

下一步能提升覆盖率的方向（按性价比排序）：

1. **GND 改用铺铜**，不要再走 290 段 MST 走线——这是当前最大的无效工作量；
2. 引入**拆线重布**（rip-up & reroute）：先布全部，再对失败的 81 条清掉周围弱网络重试；
3. 键位网络再按 X 细化分组，减少长距离跨带。
